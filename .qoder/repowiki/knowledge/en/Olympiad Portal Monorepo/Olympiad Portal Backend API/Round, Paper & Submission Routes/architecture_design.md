Three sibling Express Router modules (`papers.js`, `rounds.js`, `submissions.js`) each export a default `express.Router()` that is mounted by the application's router index. All routes delegate persistence to a shared Prisma client imported from `../lib/prisma.js`. Authentication/authorization is applied via the `requireRole` middleware from `../middleware/auth.js` (used on paper upload for `organiser` and submission creation for `educator`). File uploads are handled inline in `papers.js` using `multer.diskStorage` writing to a local `uploads/papers` directory; paper/memo URLs are stored as relative paths in the `Paper` model. Business logic lives at the route layer: `submissions.js` performs immediate auto-marking against the round's `paper.memoAnswers` JSON to compute a percentage score and create a `Result`; `papers.js` gates paper downloads based on the round's `state` (`open` or `released`). Idempotency is enforced via a unique `idempotencyKey` constraint on `Submission`, with duplicate-key errors caught and returned as successful responses. Email receipts are sent asynchronously after submission via `sendSubmissionReceipt` from `../lib/email.js`.
